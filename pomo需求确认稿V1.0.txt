1. 产品定位

pomo 是帮助用户理解金钱现实代价的 Android 手机 App。
用户输入金额，或查找商品／服务并选择报价后，通过多种生活化比较，理解这笔钱对应的收入时间、储蓄时间和日常购买力。

目标用户为对金钱数额及经济代价缺乏具体感知的普通年轻人，以女性为主要目标用户。
背景场景包括消费决策、存款目标及婚恋中的经济期待。这些是项目发起人的观察与需求来源，不作为未经核实的统计结论展示。

表达原则：客观、中性，展示事实、计算依据和估算条件，让用户自行判断。不使用说教、羞辱或刻意制造焦虑的文案，不把全国统计参照当作每个人的经济情况。

3. 核心使用流程

3.1 输入金额
打开 App → 单输入框输入金额 → 解析人民币金额 → 默认进入全国参照结果 → 左右滑动查看多张卡片。
已确认支持“10000”“1万”“100万元”等写法。
不要求先选择消费或存钱场景，也不要求先填写个人资料。

3.2 输入商品
输入商品名称 → 联网查找候选商品 → 用户选择具体型号／规格 → 查看来源及价格 → 用户选定报价 → 进入比较结果。
同一商品有多个报价时，不由系统直接替用户选定价格。

3.3 输入服务
输入服务名称 → 必要时补充城市 → 选择具体服务／套餐／时长及报价 → 进入比较结果。
城市不是所有查询的前置条件，首页仍为单输入框。

3.4 查价失败或没有合适候选
允许手动填写价格 → 标注为“用户输入价格” → 继续进行价值比较。
商品选择和报价选择可在设计阶段合并或分步呈现，最终交互待定。

4. 输入与报价规则

4.1 默认币种为人民币。
4.2 联网查价优先面向中国大陆，以人民币报价为主。
4.3 候选项需能区分影响价格的型号、规格、套餐、服务时长等信息。
4.4 报价展示来源和价格，并记录查询日期及适用规格；服务报价需明确对应城市。
4.5 不将不同规格或不同套餐的价格混为同一比较对象，不将城市服务报价描述为全国统一价。
4.6 查询无结果、失败或不合适时，均保留手动填写价格的路径。
4.7 非人民币报价、模糊输入、金额上下限及小数精度的具体规则待定。

5. 比较卡片

5.1 卡片组成
每次比较由系统自动决定数量，但不少于10张；离线基础比较也应满足该要求。
第1张：赚取这笔钱需要多久。
第2张：存下这笔钱需要多久。
其余：由系统自动选择多种合适的日常商品购买力比较，并在适合且有依据时提供直观尺度比较。
不固定每次使用同一组日常商品，不能用重复内容或虚构数据凑足卡片数量。

5.2 操作
左右滑动切换卡片。
底部圆点指示当前卡片位置。
结果页提供“全国参照／个人情况”切换，不在同一卡片并排展示两套结果。
具体卡片上限、非固定卡片排序及切换动效待设计。

5.3 日常购买力
用同一金额可购买的日常商品数量帮助理解金额。
参照商品需明确单价、规格及来源。
示意文案：“相当于约 X 袋某规格大米。”其中数值应由数据计算，不在需求阶段虚构。

5.4 大数量的直观尺度
当数量难以理解时，可用空间等尺度表达，如“约可装满 X 间100平方米的房间”。
空间比较应有层高、单件体积、包装及堆放利用率等依据，标明估算条件。
100平方米房间只是已讨论的表达示例，并非强制每次出现的卡片。
没有可信尺寸或体积数据时，不虚构装载量；使用其他有依据的参照。

6. 全国参照与个人情况

6.1 全国参照
每次默认使用中国全国统计数据。
具体统计指标、适用人群、年份、来源和工作时间口径尚未选定，当前不写入任何具体统计数值。
工资、居民人均可支配收入、平均数和中位数含义不同，实施前需明确取舍，不能混用。
若用居民收入与消费支出相减，只能解释为对应统计模型下的结余估算，不能直接声称是普通打工者的实际储蓄。

6.2 个人情况
结果页允许填写或调整：每月到手收入、每月生活开支。
个人参数保存在手机本地；下次使用个人计算时自动带入，可随时修改或清除。
保存个人参数后，新查询默认仍使用全国参照。
首次切换个人情况且尚无参数时，先补充参数。

6.3 已明确的个人计算关系
每月结余 = 每月到手收入 - 每月生活开支。
赚取时间（月）= 目标金额 ÷ 每月到手收入。
储蓄时间（月）= 目标金额 ÷ 每月结余，适用于每月结余大于0的情况。
这些是基于输入的静态换算，不代表未来收入和开支一定不变。
每月结余小于或等于0时，不能给出有限的储蓄年限；具体提示文案待定。
收入为0等边界输入、时间单位、取整方式及是否考虑收益或通胀，尚待明确。

7. 数据依据与离线能力

7.1 卡片简短标注来源与计算依据，点击后查看详细说明。
7.2 详情根据卡片类型展示统计年份、查询日期、适用人群、规格、计算方式和估算假设。
7.3 App 内置一套全国统计数据及日常商品参照数据，保证首次安装、从未联网时也能进行基础比较。
7.4 断网时使用本地可用数据，标注统计年份；不把内置或缓存参考价格冒充实时价格。
7.5 商品／服务联网查价失败时，可手动填价继续。
7.6 联网后支持基础数据更新；更新触发方式、频率、版本策略及具体服务方案待定。
7.7 内置数据的字段、覆盖的参照商品和空间估算参数需在数据方案阶段落实。

8. 本地历史记录

8.1 无需账号，在手机本地保留历史查询，支持重新查看。
8.2 支持删除单条记录、清空全部记录。
8.3 回看保留当时价格和比较结果，并标注日期，不自动用新数据覆盖。
8.4 提供“按最新数据重新计算”入口，由用户主动触发。
8.5 历史保存期限、个人模式参数如何随记录保存、重新计算后新旧记录关系待定。

9. 保存与分享

9.1 支持保存当前单张卡片为图片，并分享给朋友。
9.2 支持保存和分享本次比较的全部卡片合集。
9.3 单张图及合集版式、合集采用长图还是多图、具体系统分享入口待设计。
9.4 导出图中如何保留必要来源、年份及估算标注，需在原型阶段落实，避免脱离 App 后产生误解。
